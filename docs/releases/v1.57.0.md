## User-visible changes

- Private Email lists saved services linked to each address. One address can serve
  multiple saved Logins. Confirmed local unlink preserves ordinary Email/Username,
  the provider account, forwarding and other associations.
- Create an address before saving a Login, then link one later. Retry uses the reserved
  address/inbox. Restored encrypted editor drafts retain their original link baseline.
- Pending verification refreshes on relevant visible screens while active and unlocked.
  Detail supports deliberate full-email reveal/copy and conceals on lock/background/exit.
  Alias detail distinguishes the confirmed destination from a pending requested change.
- Loox Member has dedicated Share Links, Send to Browser and Family roots with
  identity-scoped lists/choosers. Family retains existing item/Space sharing scope.
- Banners, buttons and wrapping labels are clearer; 149 mapped keys have EN/VI/JA
  values. New secondary/success/warning body roles have a tested 4.5:1 content contrast
  floor; existing brand/icon/control color contracts remain intact.
- Disabled signed domain entries explain availability. **`loox.pw` remains disabled**.
  No production domain activation, mail-routing/default change or backend deployment
  is included. Existing issued address namespaces remain immutable.

## Security, privacy and compatibility

- Historical signed hostname proof resolves issued addresses only; unproved mappings
  cannot produce a copyable nonlegacy address or enable new creation.
- Identity/generation guards prevent stale verification and link writeback. Unlink uses
  one local SwiftData save with rollback; it is not a cross-device atomic transaction.
- Additive encrypted hostname/proof/revision/generation and optional draft-baseline
  fields have legacy nil/zero defaults. Backward decode/sealed round trips passed.
  No SwiftData record/schema or CloudKit record-type/mapping change is introduced.
- Older-binary rewrites and mixed-version devices remain unverified. A reviewed higher
  build fix-forward must preserve encrypted fields and state guards or revalidate them.
- Approval Mode remains independent of opt-in vault-item sync. Review found no newly
  introduced plaintext endpoint, secret logging or unencrypted sensitive persistence.
- [Independent review](https://github.com/bervion/Loox/blob/3e7e5515f2a5138ebb3426b29f32ddbe5f84cda0/plans/261007-1825-loox-member-and-private-email-ux-overhaul/reports/implementation-review.md)
