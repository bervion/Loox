# Architecture

A high-level map of the repository. The detailed, maintained description is [docs/codebase-summary.md](https://github.com/bervion/Loox/blob/main/docs/codebase-summary.md); UI rules are in [docs/design-guidelines.md](https://github.com/bervion/Loox/blob/main/docs/design-guidelines.md). "Vaultify" is the internal codename and survives in bundle IDs, target names and the `.vaultify` backup extension; the product name is Loox.

## Targets

All targets are declared in `Project.swift` and generated by Tuist.

| Target | Product | Platforms | Bundle ID | Notes |
|---|---|---|---|---|
| `Vaultify` | App | iPhone, iPad, Mac | `com.bervion.vaultify` | Features, design system, services, analytics. Links `FirebaseAnalyticsCore` and `FirebaseCrashlytics`. |
| `VaultifyAutoFill` | App extension | iPhone, iPad | `com.bervion.vaultify.autofill` | AutoFill Credential Provider: passwords, passkeys, one-time codes, save and generate. |
| `VaultifyAutoFillMac` | App extension | Mac | `com.bervion.vaultify.autofill` | Same sources as the iOS extension with a narrower capability set (no save or generate). Platform differences live in `#if canImport(UIKit)` branches. |
| `VaultifySafari` | App extension | iPhone, iPad | `com.bervion.vaultify.safari` | Safari web extension: a Manifest V3 bundle in `VaultifySafari/Resources/` plus a native message handler. |
| `VaultifyTests` | Unit tests | iPhone simulator | | XCTest and Swift Testing, hosted by the app. Includes crypto vectors and frozen parity fixtures. |
| `VaultifySnapshotTests` | Unit tests | iPhone simulator | | Snapshot tests using swift-snapshot-testing. |
| `VaultifyUITests` | UI tests | iPhone simulator | | |

The app embeds the iOS extensions on iOS destinations and the Mac AutoFill extension on macOS. Only the app target links Firebase; the extensions carry their own privacy manifests and no telemetry.

## VaultifyCore

`VaultifyCore/` is compiled into the app and every extension (it is a source glob, not a framework). It holds everything that must behave identically on both sides of the App Group:

| Directory | Contents |
|---|---|
| `CArgon2/` | Vendored Argon2 reference C (`ref.c`, `core.c`, `blake2/`). |
| `Crypto/` | `KeyHierarchy` (KEK derivation and Vault Key wrapping), `KdfParams` (profiles and import bounds), `AESGCM`, `Argon2`, `SecureBytes`, `CryptoRandom`, `ArtifactCrypto`, `VaultKeyPairing`. |
| `Keychain/` | `VaultKeyBundle` (the wrapped-key envelope on disk), `BiometricKeyStore`, `ExtensionSessionStore`, `KeychainStore`. |
| `Models/`, `Types/` | Sealed payload types, item semantics, the item template registry and `ItemCapabilityResolver`, which decides what each item kind may do externally. |
| `Store/` | `VaultStore`, the SwiftData store of sealed records in the App Group container. |
| `Passkey/` | WebAuthn types and ES256 primitives. |
| `Sharing/`, `Relay/`, `Subscription/` | Approval Mode crypto kernel and models, relay command signing contracts, membership tiers and gates. |
| `VaultReader.swift`, `VaultWriter.swift` | How extensions read logins, codes and identities and save a new login. |
| `WebExtensionRouter.swift` and friends | The Safari extension's native command router and fill payload builder. |
| `SharedConfig.swift` | App Group, keychain group and file locations shared by all targets. |
| `Theme/`, `Platform/` | Shared theme values and platform adapters. |

## App layer

```
Vaultify/
├── App/            VaultifyApp (@main), AppEnvironment (root object graph), RootView (onboarding / locked / unlocked routing, auto-lock, privacy shield), SettingsStore
├── Security/       VaultSession (create, unlock, biometric unlock, lock, recovery, master-password change), RecoveryKey, Extra Protection
├── Data/           VaultRepository: decrypt-on-unlock cache, CRUD, trash, favorites, Spaces, tags, personas
├── Audit/          Security audit engine: rules, scoring, fix queue
├── Services/       ImportExport (VaultBackup), Sync (CloudSyncService, SyncCoordinator, VaultKeyEscrowService), Sharing, Relay, Capabilities (signed config), Watchtower (HIBP), FaviconService, password generator, TOTP, clipboard, notifications
├── Analytics/      Typed event catalog, AnalyticsEngine, CrashReporter and its key catalog
├── DesignSystem/   Tokens, typography, Polaris icon system, themed components
└── Features/       Onboarding, Unlock, Main (tab shell), Home, Items, Folders, ItemDetail, ItemEditor, Generator, Search, Watchtower, Passkeys, Personas, Profile, Sharing (Approval Mode, LooxLink, QuickView), ImportExport, Settings, Subscription, Tutorial
```

## Data flow

1. **Unlock.** `VaultSession` derives the KEK (Argon2id, off the main actor) or reads the biometric Keychain item, unwraps the Vault Key from `vault-keybundle.json` and hands it to the repository.
2. **Read.** `VaultRepository` loads the sealed records from `VaultStore`, decrypts them into an in-memory cache and publishes them to SwiftUI. Lists, search and Security work on that cache. Locking clears it.
3. **Write.** Edits re-seal the item blob and save it through `VaultStore`; plain columns (favorite, pinned, archived, timestamps) are updated without re-sealing.
4. **Extensions.** `VaultReader` opens the same store from the App Group container after its own unlock (biometric key or master password) and answers AutoFill and Safari requests through `ItemCapabilityResolver`, so developer secrets and unknown item kinds never surface. `VaultWriter` saves a new login created from AutoFill; the app reloads on foreground.
5. **Sync (optional).** `CloudSyncService` pushes and pulls sealed records and folder metadata to the user's private CloudKit database. `VaultKeyEscrowService` mirrors the recovery envelope and carries device-pairing hand-offs.
6. **Network features (optional).** Quick Link, Quick View, Approval Mode and Private Email each have a client in `Services/` or `Features/Sharing/` that seals data on the device before calling their service; availability is driven by signed configuration documents verified in `Services/Capabilities/`.

## Conventions worth knowing

- Every user-facing string lives in `Vaultify/Localizable.xcstrings` with English, Vietnamese and Japanese values; the Safari extension's web strings are in `VaultifySafari/Resources/_locales/`.
- Icons render through `VaultIcon` and the Polaris asset catalog; SF Symbols are only offered as extra choices in the icon picker and must exist on iOS 17.3.
- Analytics events come from the typed catalog only and never carry item names, values, websites or search terms.
- Colors, spacing, radii and motion come from design tokens; screens compose components and never hard-code visual constants.
