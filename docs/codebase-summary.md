# Vaultify (iOS) — Codebase Summary

> **Brand:** ships as **"Loox Password"** (display name **"Loox"**) since 2026-07. "Vaultify" remains
> the internal codename everywhere the user can't see it: bundle ids (`com.bervion.vaultify*`),
> App/keychain groups, scheme/target/module/folder names, log subsystems, the `.vaultify` backup
> extension, and the HPKE envelope info string (crypto binding — must never change).

Native **SwiftUI** rewrite of the Flutter Vaultify — a zero-backend, on-device password
manager. **iPhone + iPad + native macOS**, iOS 17.3+ / macOS 15+, Apple-native UI/UX, with the **Polaris SVG icon set**
(vector-PDF template assets) instead of SF Symbols. ~17,000 LOC across ~200 Swift files.

## Security model
- **KDF:** Argon2id (canonical reference C, OWASP 64 MiB/t=3/p=4) → KEK. Verified against the published v1.3 KAT.
- **Key hierarchy:** random 256-bit Vault Key, wrapped (AES-256-GCM) by the password KEK and an Emergency-Kit recovery KEK; biometric path stores the Vault Key in a `.biometryCurrentSet` Keychain item (Secure Enclave-gated).
- **At rest:** every item is a single AES-256-GCM sealed `ItemSecret` blob in SwiftData; only low-sensitivity metadata (timestamps, favorite, trashed) is plaintext. Decrypted into an in-memory cache on unlock; cleared on lock.
- **Hygiene:** `SecureBytes` (mlock + memset_s), local-only auto-expiring clipboard, auto-lock (single `autoLock` timer covers foreground idle AND backgrounding: `.immediate` = lock the moment the app hides, longer windows survive a copy-into-another-app round trip; the old always-instant "lock on background" toggle is gone), app-switcher privacy shield, HIBP via k-anonymity (only 5 hash chars leave the device). Deliberate locks (shake OR Settings "Lock Now" → `session.lock(deliberate:)`) require slide-to-unlock before Face ID so the owner's face can't instantly re-open a vault they just chose to lock.

## Vault Organization (Folders, Tags & Identities)
- **Folders ("Spaces")** — one per item via `VaultItem.folderId`; `nil` = Unfiled. `FolderRecord` keeps the **name sealed** (AES-GCM under the Vault Key) while icon/color/sortIndex/sync metadata stay plaintext so the Spaces grid renders without unsealing. CRUD + counts + reassign-on-delete (members → Unfiled, items never deleted) live in `VaultRepository+Folders`.
- **Tags** — many per item, stored lightweight as `tags: [String]` inside the sealed `ItemSecret` (no separate record). Aggregated case-insensitively by `allTags()`; surfaced as `#` chips.
- **Recents** — `ItemRecord.lastUsedAt` (plaintext, device-local, NOT synced); `markUsed` writes it without re-sealing/`dirty` on copy/reveal; powers Home's "Recently Used".
- **Rotation reminders** — `ItemRecord.rotateDays` (plaintext: 0=off, 15/30/90=enabled) + `passwordChangedAt` (plaintext: last explicit password change, or `nil` → use `createdAt`). Both device-local for now. `RotationStatus` struct (pure, `nonisolated`) evaluates state (ok/overdue/soon/stale) + display label from metadata + current date. `RotationNotificationService` sends OS local notifications. Item editor includes "Rotation reminder" picker. Currently NOT synced to CloudKit; per-item cadence sync may be added later behind the `VAULTIFY_ICLOUD` gate.
- **Identities & avatars** — `ItemCategory.identity` carries fields: Full Name, Email, Phone, Address, Date of Birth, ID Number (protected). `ItemRecord` gained two synced columns: `isDefaultIdentity: Bool` (exactly one active identity is marked default) + `avatarSealed: Data?` (AES-GCM-sealed ≤256px JPEG). `VaultRepository+Identity` adds `activeIdentities`, `defaultIdentity`, `setDefaultIdentity` (bumps `updatedAt` for sync), `identityRemovalGate` (blocks trashing the last active identity). `VaultRepository+Avatar` handles `setAvatar`/`avatarImage` (PhotosPicker → downscaled JPEG via `AvatarImage.downscaledJPEG`). Default-identity is a synced column (not a local SettingsStore flag) because it must survive logout and sync cross-device; sync gate uses whole-record LWW by `updatedAt`. `normalizeDefaultIdentity()` runs on reload to converge conflicts by max(`updatedAt`). **Onboarding:** new "What should we call you?" step (`NameStepView`) creates/selects the default identity. **Profile UI:** `ProfileScreen` displays avatar, default-identity toggle, tap-to-copy fields, payment-cards section, zero-identity empty state; avatar from PhotosPicker.
- **Home dashboard** (`HomeScreen`): Folder-switcher header + Quick actions (Generator, Settings, …) + TOTP quick-view + "Needs attention" (rotation + weak passwords via `RotationStatus`) + Favorites + All Items (pinned-first, category-grouped). Built from DS-spec components (`HomeHeaderBar`, `QuickActionTile`, `TotpCardView`, `AttentionCell`). Home header has avatar button → `ProfileScreen`.
- **Default space:** first launch seeds a renameable **"My Vault"** space; new items default to the primary space.
- **Navigation (4 tabs):** **Home** = redesigned DS-compliant dashboard (folder switcher, quick actions, TOTP, "Needs attention", Favorites, All items). **Items** = organization browser (Spaces + Create Space · Categories · Tags · Archive · Recently Deleted). **Watchtower** = security monitoring (ScoreRing, StrengthCard, issue categories: Compromised/Reused/Weak/Missing2FA). **Search** = smart search (token-AND over title/fields/tags + Space name). Each tab owns a NavigationStack sharing `vaultNavigationDestinations()`.
- **Pinned / Archived / Frequently-Used / Rotation:** `pinned`/`archived`/`useCount` and `rotateDays`/`passwordChangedAt` are plaintext `ItemRecord` columns (codec untouched). `reload()` splits items 3-way (live / archived / trashed) so archived stays out of every normal surface (Home, Items, Search, counts, AutoFill) but lives in Archive. `togglePin`/`archive`/`unarchive` are column-only (no re-seal, no `updatedAt` bump); `markUsed` bumps `useCount`; rotation metadata updates don't dirty the item (preserve seal).
- **Back-compat (critical):** `ItemSecret`/`PortableItem` use a custom `init(from:)` that `decodeIfPresent`s `tags` (default `[]`) so pre-existing sealed blobs and old backups still open.
- **CSV/backup:** export adds `folder` + `tags` columns; import matches/creates folders by name. Encrypted `.vaultify` backups also carry passkeys as `PasskeySecret` payloads inside the passphrase-encrypted sealed JSON; legacy item-only backups still decode. CSV never includes passkey material. **CloudKit:** `FolderRecord` syncs as `"VaultFolder"` (sealed name + metadata), `PasskeyRecord` as `"VaultPasskey"` (sealed credential + largeBlob, LWW, tombstones wipe key material; locked-write envelope staging never syncs), `ItemRecord` carries `isDefaultIdentity` + `avatarSealed` as synced fields, behind the `VAULTIFY_ICLOUD` gate; tags ride inside the item blob.

## Theming & Wallpaper
Design-System aligned, simplified. **Core** in `VaultifyCore/Theme/` (shared into app + AutoFill extension): `AppTheme` (semantic palette, packed `0xRRGGBB`); built-ins **Day + Night** (Day-Classic / Night-Tinted code retained, not surfaced); **7 accent presets** (blue/indigo/teal/purple/pink/graphite/mono) with light + dark hues (`AccentColor.swift`); custom RGB removed; `ThemeSettings` (Codable — theme ref + accent selection + auto-night + font scale); `ThemePalette.resolve` (pure); `ThemeReader` (App-Group persist + one-time migrate from `appearance_mode`); `WallpaperFeature.decorativeEnabled = false` gates decorative backgrounds (wallpaper engine code retained for future re-enable).
- **App layer:** `ThemeStore` (`@MainActor @Observable`) resolves the active `AppTheme`, persists, drives `\.appTheme` + `.tint` + `preferredColorScheme` from the root, and forces the window `overrideUserInterfaceStyle`. `setTheme` resets the selected theme to its own defaults (clears per-theme accent overrides) so it always looks as designed. `ThemeHolder` is the synchronous snapshot for `VaultColors`, whose surfaces (`surface/fill/groupedBackground/separatorColor`) are **dynamic `UIColor`s** that re-resolve on a color-scheme flip — staying in lock-step with trait-driven foregrounds. **Design tokens** (`DesignSystem/Tokens/`: `Space`·`Radius`·`Metric`·`Elevation`·`Motion`) + `VaultType` typography roles + **derived** semantic colors (`AppTheme+Tokens.swift`: surfaceFloatingSolid / surfacePressed / accentSoft / accentPress / icon* / textDisabled / *Soft / onDestructive, computed so every builtin theme gets them) round out the system; `ThemeRole` now also covers icon + disabled + accentSoft + onDestructive. Reusable components (`DesignSystem/Components`): `ThemedCard`, `.themedForeground(role)`, `.appBackground()`, `.themedFormBackground()`, button styles (`.themedProminent/.themedTinted/.themedDestructive`), `ThemedToggleStyle` (draws the switch from theme colors — native `.tint` does not reach `Toggle` in `Form`/sheets), and `.themedColorScheme()` (applied at every sheet / full-screen-cover root so their system chrome — nav title, `Form` section headers/footers, pickers — follows the theme instead of the device appearance). Feature views use semantic theme colors throughout (no raw `.primary/.secondary/.red/.white` on themed surfaces). `accentForeground` is **derived by WCAG contrast** (`RGBMath.onColor`) for presets, so text on filled accent always clears AA. `BrandLogoMark` renders the app brand from the `BrandLogo` asset.
- **Wallpaper:** Engine (solid / gradient / pattern / image / animated mesh) is fully implemented but **gated OFF** by `WallpaperFeature.decorativeEnabled = false`. `WallpaperView` renders flat fills when gated. Mesh code (Telegram's CPU `generateGradient` frames via `CAKeyframeAnimation`, no Metal) retained for future re-enable behind the flag. Settings UI simplified: no wallpaper picker, no custom-theme editor surfaced. Reduce Transparency still respected when engine is re-enabled.
- **Settings UI** (`Features/Settings/Appearance`): theme selection / accent preset picker / auto-night (off·system·scheduled·brightness) / text size / reduce motion. Custom theme editor + `.vaultheme` import/export hidden (code retained). All strings EN + VI + JA. Tests: `VaultifyTests/ThemeEngineTests`.

## Analytics (GA4)
`Vaultify/Analytics/` — provider-fanout engine over Firebase Analytics, pinned `firebase-ios-sdk` 12.16.0, product **`FirebaseAnalyticsCore`** (GoogleAppMeasurementCore: full GA4, **no AdSupport/IDFA/ATT**), app target ONLY (extensions carry no telemetry). `AnalyticsEngine` (MainActor facade; consent gate, DEBUG `AnalyticsPolicy` asserts, bulk `runSuppressed`, dedup screen views) → `AnalyticsProvider` conformances (`FirebaseAnalyticsProvider` + DEBUG console mirror). Typed catalog in `AnalyticsEvents.swift` is the only place names/params are spelled; privacy contract: item TYPES, `AnalyticsBucket` counts, product IDs, setting states — never names/values/sites/search terms. GA4-limit compliance is test-enforced (`AnalyticsEventTests` over `auditSamples`). Consent: `SettingsStore.analyticsEnabled` (default ON, opt-out toggle in Settings → General on iOS and the Mac General pane; live via didSet). Bootstrap in `VaultifyApp.init` — without a bundled `GoogleService-Info.plist` (`Vaultify/Resources/`) Firebase never configures and the app runs with analytics dark. User properties: `subscription_tier` (follows verified transactions), `app_language`, `icloud_sync`. Manual `screen_view` via `.analyticsScreen("name")` (`FirebaseAutomaticScreenReportingEnabled=false`).

## AutoFill Credential Provider extension
**Targets:** `VaultifyAutoFill` (iOS/iPadOS) + `VaultifyAutoFillMac` (macOS 15+, same sources and bundle id, narrower capability set — macOS has no save/generate request types) + `VaultifyCore` (shared code). Integrates with system credential request flows. The hosting controller branches on UIKit vs AppKit because `ASCredentialProviderViewController` is a UIViewController on iOS and an NSViewController on macOS; macOS runtime (App Group container, Touch ID, real fill) still needs verification on a signed Mac build.
- **Face ID unlock** — extension unlocks with biometric (1 tap) via `BiometricKeyStore`, fallback to master password. Uses **shared Keychain Access Group** `$(AppIdentifierPrefix)com.bervion.vaultify.shared` added to both targets' entitlements; allows extension to read the biometric-gated Vault Key. Silent one-time migration moves enrolled users' keys from legacy per-app keychain to shared group on next in-app unlock (`VaultSession.biometricUnlock`). `provideCredentialWithoutUserInteraction` returns `userInteractionRequired` (no silent fill).
- **Create new login from extension** — registration form includes "＋ Create new login" (optional modal): generates password (moved to `VaultifyCore/PasswordGenerator.swift`), prefills site domain + username/email (from default identity via `VaultReader.defaultIdentityUsername`), saves via new `VaultifyCore/VaultWriter.swift` (recoverable — throws instead of `fatalError`). App reloads on foreground (`RootView.phase(.active)`); pushes to CloudKit on next sync.
- **Passkeys** — shared WebAuthn ES256 primitives emit a fixed Vaultify AAGUID and per-credential flags (`UP|UV|BE|BS` for new credentials; legacy credentials keep `UP|UV`). `PasskeyVault` is store-injected, stores Vault-Key-sealed `PasskeySecret` payloads in `PasskeyRecord`, dedupes atomically by RP + user handle, exposes metadata-only `PasskeyInfo` to the app, and deletes passkeys on `eraseAll()`. The app has a Settings → Passkeys screen (grouped by site, detail/delete sheet, quarantine banner) and login item details show passkeys whose RP matches the item's host via conservative suffix matching. The passkey detail sheet shows a favicon + a backup-status badge derived from the stored BE/BS flags (`PasskeyBackupStatus`: Backed up / Backup eligible / This device only), 1Password-style; `PasskeyInfo` carries the non-secret `flags` for this, and the "Backed up" pill downgrades to "This device only" while `iCloudSyncEnabled` is off (the flags speak for the RP; storage truth requires the `VaultPasskey` sync plane). Passkeys sync via CloudKit (`VaultPasskey`, folder-parity LWW on `updatedAt`): deletion/replacement tombstones wipe the sealed material so removals propagate instead of resurrecting, `usedAt` stays device-local, and recovery-key restore brings passkeys back with the items. The extension uses `UnlockGate` for Face ID/master-password unlock, validates ES256 + excluded credentials pre-unlock, shows a registration confirm card or multi-account assertion picker post-unlock, awaits identity-store removal/save before completing registration, and updates `lastUsedAt` after assertions. App unlock/reload publishes `ASPasskeyCredentialIdentity` entries through `CredentialIdentityService.refresh(items:passkeys:)`, serialized with a generation guard so stale refreshes cannot resurrect deleted identities.
- **iOS 18 automatic passkey upgrades** — `VaultKeyBundle` now carries an HPKE `Curve25519_SHA256_ChachaPoly` envelope keypair: public key readable while locked, private key AES-GCM sealed under the Vault Key. `performWithoutUserInteractionIfPossible(passkeyRegistration:)` gates on the shared "Automatic passkey upgrades" setting, ES256 support, public key presence, and excluded credentials; success stores an `envelopeSealed` passkey record and publishes its identity without logging RP/userName. Unlock-time hooks verify the keypair, open/migrate envelope records into normal Vault-Key sealing, dedupe newest RP+userHandle, prune replaced/quarantined identities, and queue a one-time Passkeys-screen notice for quarantined sites.
- **Passkey `largeBlob` extension (iOS 18+)** — interactive ceremonies service the WebAuthn `largeBlob` extension: registration advertises support when the RP requests it; assertion reads the stored blob or persists a written one (`PasskeyRecord.largeBlobSealed`, AES-GCM under the Vault Key). The intent is extracted at the iOS 18 entry points into a version-agnostic `PasskeyLargeBlobDirective` so the shared ceremony still compiles for 17.3; the locked silent-upgrade path never touches largeBlob. Provider AAGUID is the frozen `9078984A-B6CA-4DA9-AA36-9BB2A3B23F02` (**follow-up:** submit name + light/dark SVG icons to the community registry `github.com/passkeydeveloper/passkey-authenticator-aaguids` so relying parties display "Vaultify").
- **Localization:** `Localizable.xcstrings` bundled into extension; `appResourceLocale` mirrored from App Group + `.environment(\.locale,)` applied at root.

## Safari Web Extension (identity + card fill, signup assist)
**Target:** `VaultifySafari` (`com.bervion.vaultify.safari`, `com.apple.Safari.web-extension`, iPhone + iPad) — an MV3 web bundle (`VaultifySafari/Resources/`: manifest, non-persistent background page, content scripts, popup, `_locales/` EN+VI+JA) plus a native handler (`SafariWebExtensionHandler` → `SafariMessageRouter` → shared `VaultifyCore/WebExtensionRouter`). Entitlements: App Group + shared keychain group only, deliberately **no CloudKit**. Permissions: `nativeMessaging, activeTab, tabs` + `https://*/*` (no `scripting`).
- **Architecture:** the background page is the single message hub — popup and content scripts never talk to native directly. Native requests are rebuilt from whitelisted keys; the matching origin ALWAYS comes from the trusted `browser.tabs` API, never from message fields. Sender gating: vault-reading commands are popup-only; content scripts get exactly `saveGate/saveLogin/neverSave` (signup assist), `inlineItems/inlineFillItem/ccFrameHello` (inline menu), and `hideSite` (kill switch, hide-only).
- **Unlock/session:** popup unlock via `BiometricKeyStore` (Face ID from the headless handler); `ExtensionSessionStore` keeps a short-lived native session (sliding ≤15 min, mirrored auto-lock, fail-closed) so repeat operations don't re-prompt. `listItemsSession` (inline menu) is served ONLY from that session — no session means `locked`, never a prompt: a page focusing a field can never summon Face ID.
- **Fill-auth model:** `getFillPayload` is the ONLY command returning vault values for page injection — single item, identity/card categories only (logins are structurally unreachable), constructed by the background page exclusively inside the two user-tap flows (popup Fill, inline-menu row tap), origin pinned to the tab before the native round trip and re-checked after it. Payload lives in locals, dropped after dispatch/10 s. Content scripts re-run classification + a visibility/editability gauntlet at fill moment (hidden-field trap, off-screen park, ancestor opacity, disabled). Cross-origin iframes: card values only, to an explicit allowlist (`js.stripe.com`, `checkout.stripe.com`, `pay.google.com`) with dual-side origin checks by explicit frameId — every other subframe has no listener at all.
- **Inline menu:** identity/card fields with tier 1-2 evidence only, trusted (`isTrusted`) focus only, closed shadow root, metadata only (titles, brand, last4). NEVER renders for credential fields (visible-password suppression + belts; logins never cross the bridge). Signup assist: generated password (popup tap, rate-limited 5/min) + in-page save overlay (submit-intent capture, 60 s TTL, Save arm delay against reverse-clickjack, `saveLogin` rate-limited 5/min/host, suppressed on iOS 26.2+ where the OS save sheet owns the flow).
- **Per-site controls** (shared defaults, hostnames only): "Never for this site" (save overlay opt-out) and the "Hide on this site" kill switch (popup footer toggle; inline-menu footer can only hide) — a hidden host gets no inline menu and no save overlay, decided natively before any key access; popup fill keeps working.
- **Invariant:** the Vault Key and bulk vault contents never cross the native→JS bridge; no command is both unauthenticated and vault-touching. Enforced by router tests + fuzz suite (`VaultifyTests/WebExtension*`, `WebExtensionRouterFuzzTests`) and JS node harnesses (`VaultifySafari/DevFixtures/*-node-tests.mjs`).

## Loox Quick View ("Open on Computer")
One-shot, field-scoped E2E handoff to any browser — the **recipient-keyed dual** of Loox Link (`Vaultify/Features/Sharing/QuickView/`, backend `looxpassword/workers/loox-quick-view` + config-plane signer keyset). Browser at `looxpassword.com/open` mints ephemeral P-256 enc+sig keys → shows QR (`LOOX-QV-QR-V1:{code}:{b64url(sha256(session_id‖enc_key_hash‖sig_key_hash)[:8])}`) + human code + SAS; app scans/enters → resolves → user picks exact fields → Face ID → re-read → seals ONLY those fields to the browser's key → browser decrypts once, render-only. Server is a blind rendezvous mailbox (no read API over the vault; IDOR impossible by construction). **Kernel** (app-only, mirrors LooxLink placement so DeviceCheck stays out of the appex): `QuickViewSessionEnvelope(+Verifier)` (`LOOX-QUICK-VIEW-SESSION-V1`, P-256 sig verified against the runtime signer key endorsed by `QuickViewSignerKeyset`/`Client` — offline-signed by the `cap-2026-02` config root, mirrors DomainRegistry — NOT a bundled key); `QuickViewPayloadSealer` (ECDH P-256 → HKDF-SHA256[salt=SHA256(kdf transcript), info=`raw("LOOX-QUICK-VIEW-PAYLOAD-V1")‖byte(1)‖raw("aead-key")`] → AES-256-GCM, IV(12)‖ct‖tag opaque; deliberately NOT the Approval-Mode ChaCha HPKE); `QuickViewSAS` (BIP-39 EN 2048, `sas-wordlist-bip39.txt`, HKDF bit-packed 2 words+2 digits); `QuickViewFieldManifest` (structural `LOOX-QV-FIELD-MANIFEST-V1` — hashes field id/kind/concealed/ordinal, never values); `QuickViewPayloadComposer` (builds shareable via `LooxLinkEnvelope.build`, appends a boundary-aware **current** TOTP as a virtual field with an AEAD-bound `valid_until`; `LooxLinkEnvelope` untouched; guard2/extra-protected TOTP fails closed). All parity-tested byte-for-byte against BE frozen vectors (`VaultifyTests/QuickViewParityTests`). **Wire is base64url everywhere** (session_id/hashes/nonces/ciphertext/aad — the app decodes base64url, not hex; the frozen vectors' hex is a test representation only). **Client** (`QuickViewAPIClient`/`Canonical`/`Attestation`): resolve (code in POST body), advisory bind (never blocks approve), upload = 3 base64url fields `{ciphertext, app_eph_pub, aad}` (aad is a single opaque blob; worker tripwire rejects exposed keys) bound by `LOOX-APP-ATTEST-QUICK-VIEW-V1`; App Attest shadow ladder. **Exposure gate** (DEC-QV-EXPOSURE-01): signed manifest `quick_view.exposure = hidden|beta|ga` (schema-2, additive; `CapabilityManifest` verifier accepts schema 1&2); `QuickViewExposureResolver` — `hidden→false`, `beta→isBetaCohort`, `ga→isBetaCohort?true:assertionRequired` (public fails closed while assertion below required, INV-QV-24); DEBUG-only `quick_view_exposure_override` for QA. Minimal device-local history (`item_id+timestamp+result` only). DEBUG targets `api-staging` (env staging, shadow). **Open (BE):** `/open` page's hand-rolled QR encoder produced undecodable QR (confirmed via jsQR: BE encoder NULL, standard lib OK) — BE fix pending; rollout is required-before-active (DEC-QV-ROLLOUT-01).
