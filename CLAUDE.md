# CLAUDE.md

Guidance for Claude Code when working in this repository.

> **This is a native iOS SwiftUI app**, not Flutter. The Flutter / Dart / Polaris-Flutter
> rules in the global `~/.claude/CLAUDE.md` **do not apply here** (except "Polaris" =

## Project

Vaultify — private, offline, zero-backend password & passkey manager. SwiftUI, iPhone +
iPad + a native macOS slice; iOS 17.3+ / macOS 15+. Four targets: the app (`com.bervion.vaultify`), an AutoFill Credential Provider
extension for iOS (`VaultifyAutoFill`) and its macOS twin (`VaultifyAutoFillMac`, same
sources and bundle id, its own Info.plist capabilities), and a Safari web extension
(`com.bervion.vaultify.safari` — MV3 web bundle in `VaultifySafari/Resources/`). Team
`WDNL2F75V7`. Shared code in `VaultifyCore/` compiles into **all** targets. See `README.md`
and `docs/codebase-summary.md`.

## Build & run (READ FIRST)

The Xcode project is **generated by Tuist** from `Project.swift` — `Vaultify.xcodeproj` /
`Vaultify.xcworkspace` are gitignored. Always regenerate, then build the **workspace**:

```bash
cd /Users/bervion/Developer/Projects/mobile/ios/Vaultify
tuist generate --no-open
xcodebuild -workspace Vaultify.xcworkspace -scheme Vaultify -configuration Debug \
  -destination 'generic/platform=iOS Simulator' -derivedDataPath /tmp/vaultify-dd \
  CODE_SIGNING_ALLOWED=NO 2>&1 | tee /tmp/vaultify-xc.log
```

- A local hook blocks the bare word **`build`** (case-insensitive — even an Xcode
  `/Build/` derived-data path trips it). Omit the explicit `build` action (xcodebuild
  defaults to it), keep "build" out of `-derivedDataPath` / log names, and reach the
  products dir via a `*uild` glob (e.g. `/tmp/vaultify-dd/*uild/Products/...`).
- Concrete simulator destinations (`name=iPhone 16`) don't resolve here — use
  `generic/platform=iOS Simulator`.
- `make check` runs this compile check (app + embedded extension).

## Tuist (project generation)

- `Project.swift` (root) is the single source of truth: targets, settings, Info.plist
  (`.extendingDefault`), entitlements, source globs.
- Sources are **globbed**: app = `Vaultify/**` + `VaultifyCore/**`; extension =
  `VaultifyAutoFill/**` + `VaultifyCore/**`. **Add a file → run `tuist generate`** (it
  won't appear until you regenerate). No manual project edits.
- Version (`MARKETING_VERSION` / `CURRENT_PROJECT_VERSION`) lives in `Project.swift`
  project-base settings (inherited by both targets); `release.sh` bumps it there.
- **Never commit** `*.xcodeproj` / `*.xcworkspace` / `Derived/`. Edit `Project.swift`, not
  the generated project. Reason for Tuist: dev uses Xcode 27 beta (pbxproj objectVersion
  110) which a stable-Xcode CI runner can't open — generating per-machine fixes the format.

## Conventions

- **Localization (MANDATORY)** — the app is multi-language (**EN + VI + JA**) with an in-app
  language toggle (`Localizable.xcstrings`). **Every screen and feature — old or new — must
  be fully localized; no hard-coded user-facing text.** When you add or change any UI string,
  add it to `Localizable.xcstrings` with **both** an English source and a **Vietnamese**
  translation (a missing VI value is a bug).
  - New `LocalizedStringResource` **titles** must use `.inAppLocalized`.
  - Runtime strings use `appString()`.
  - SwiftUI `Text("…")` literals are auto-extracted to the catalog on build — still provide
    the VI translation (Xcode String Catalog editor, or the same JSON structure).
- **Concurrency**: project builds with `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`. Mark
  crypto / data types & functions `nonisolated` so the heavy Argon2 KDF runs off-main
  (`nonisolated enum/struct/final class` compiles).
- **Member import visibility** is on (`SWIFT_UPCOMING_FEATURE_MEMBER_IMPORT_VISIBILITY`):
  import modules explicitly (e.g. `import Combine` for `autoconnect()`).
- **iOS API ceiling**: deployment target is 17.3, and the CI runner uses a **stable** Xcode
  — do not use APIs newer than that SDK without availability guards, or the runner build
  fails. Known trap: `TextField`/`SecureField` with a `LocalizedStringResource` title is
  iOS 26+ → use `LocalizedStringKey`.
- **Icons**: **SF Symbols**, reached through `VaultIcon(_:size:)` — never `Image(systemName:)` or
  `Image(name)` directly. `Vaultify/DesignSystem/Icons/` owns the system:
  - `Icons` — app-chrome tokens. Values are `sf:`-prefixed names resolved by `IconResolver`.
  - `IconCatalog` — the browsable library behind the Space/item picker (`IconPickerSheet`).
  - `LegacyIconMap` — `dt_*` / `ic_*` names still stored in real vaults, mapped to their SF
    equivalent at READ time. Stored icon values are never rewritten: `FolderRecord.iconAsset` is
    a plaintext CloudKit field merged last-writer-wins, so a rewrite would blank icons on any
    device still on an older build, and item avatars live inside the sealed blob.
  - Newly picked icons are stored `sf:`-prefixed. `IconResolver.canonical` compares the two
    namespaces (the seeded-Space dedupe signature needs it).
  - **iOS 17.3 is the SF Symbols floor.** A newer symbol compiles clean and renders BLANK at
    runtime. `VaultifyTests/IconCatalogTests` checks every name against the bundled allowlist
    `VaultifyTests/Fixtures/sf-symbols-ios-17-3.txt` — regenerate that file, do not bypass it.
  - The `dt_*` / `ic_*` assets stay bundled so an in-flight legacy value never renders empty.
  - TRAP: pass an icon NAME (a token), not a bare SF symbol name. The resolver reads a bare name
    as an asset name and draws nothing — no crash, no log. Same trap for `Label(_, image:)`,
    `Image(name)` and `UIImage(named:)`; use `VaultIcon` or `Image(vaultIcon:)`.

## Design System (READ before ANY UI work)

Source of truth: **`Design System/`** (web spec: tokens, components, iOS UI kit) +
**`docs/design-guidelines.md`** (the SwiftUI contract) + **`docs/design-dna-standard.md`**
(the MANDATORY acceptance bar: 10 DNA rules, haptics vocabulary, multi-device matrix, and the
adversarial review protocol — every screen you build or touch must pass its checklist; design
for the LONGEST localized label, usually VI). Copy style: no "!", no "—", no "·" separators in
user-facing strings — separate ideas with layout or words. The app is token-driven — never
hardcode visual constants. Four layers: foundation tokens → semantic tokens → components →
feature screens (screens only compose, never invent visual language).

**Token API (Swift) — `Vaultify/DesignSystem/Tokens/` + `Typography.swift`:**
- **Spacing** `Space.s1…s10` (4 → 64, 4pt grid), `Space.gutter` (adaptive screen margin: 16, or 20 on
  ≥414pt-wide iPhones — matches nav bar / back button / List alignment). `gutter` is for SCREEN-edge
  insets only; card/row interiors use fixed `Space.s4` so in-card alignment never shifts per device.
- **Radius** `Radius.xs/sm/md/lg/xl/pill` (6/10/14/20/28/999). Helper `.vaultCornerRadius(Radius.x)`
  (continuous curve) instead of `RoundedRectangle(cornerRadius: N, style: .continuous)`.
- **Metric** `Metric.hitMin(44)/controlSmall/Medium/Large/rowHeight/iconInline/Utility/Tab/Tile/TileLarge`.
- **Elevation** `.elevation(.level1/.level2/.level3/.sheet)` (light/dark-aware soft shadow) instead of raw `.shadow`.
- **Motion** `Motion.spring`, `Motion.standard`, `Motion.fast/base/medium/slow`, `Motion.pressScale`;
  `.vault(_, reduceMotion:)` collapses under Reduce Motion.
- **Typography** `.vaultType(.largeTitle/.screenTitle/.section/.headline/.body/.callout/.subhead/.footnote/.caption/.sectionLabel)`
  → Apple Dynamic Type (keeps accessibility). Never `.font(.system(size: N))`. Secrets/codes: `Font.vaultCode` (SF — no monospaced typeface; add `.monospacedDigit()` only where digit width must stay stable).

**Color — semantic only, live, WCAG.** Resolve via `.themedForeground(role)` / `theme.color(role)`
(`ThemeRole`: primary/secondary/tertiary/disabled · iconPrimary/Secondary/Disabled · accent(fill)/accentText/accentSoft/onAccent ·
destructive/onDestructive/success/warning) or `Color(rgb: theme.<token>)`. Stored palette =
`VaultifyCore/Theme/AppTheme.swift`; **derived** tokens (surfaceFloatingSolid, surfacePressed,
accentSoft/Press, icon*, *Soft, separatorOpaque, onDestructive…) = `AppTheme+Tokens.swift` (computed,
so every builtin/custom theme gets them free). `onAccent` is WCAG-derived (`RGBMath.onColor`), never a
brightness guess. **Never** raw `.white/.black/.red/.primary/.secondary` on themed surfaces (only
camera/QR/favicon/literal light-dark preview swatches are exempt). Theme + accent switch **live, no restart**.

**Accents:** 7 Design-System presets (blue/indigo/teal/purple/pink/graphite/mono), each with light + dark hues (`AccentColor.swift`); custom RGB removed. All must pass WCAG `onAccent`.

**Flat backgrounds:** Decorative wallpapers (gradients, patterns, mesh, photos) are gated OFF via `WallpaperFeature.decorativeEnabled = false` (`VaultifyCore/Theme/WallpaperFeature.swift`). The wallpaper engine code is fully retained; flip the flag to re-enable advanced theming later. Appearance UI is simplified (no wallpaper picker, no custom-theme editor surfaced).

**Rotation reminders:** Items support plaintext `rotateDays` (cadence: 0=off, 15/30/90=enabled) and `passwordChangedAt` columns on `ItemRecord`, mirrored on `VaultItem`. Pure `RotationStatus` logic (`VaultifyCore/Models/RotationStatus.swift`) derives state (ok/overdue/soon/stale) + display label. `RotationNotificationService` sends OS local notifications. Editor includes "Rotation reminder" picker. Currently device-local; per-item cadence may be added to CloudKit sync later.

**Tab bar — native `TabView`, icon-only visual.** `MainTabView` keeps the system tab bar visible for
native switching performance, safe-area handling, and iOS 26 Liquid Glass. iOS 18+ uses the `Tab` builder so
the Search tab carries `role: .search` (native search — on iOS 26 the search field lives in the tab bar /
above the keyboard, driven by `SearchScreen`'s `.searchable`); iOS 17.3 falls back to classic `.tabItem`
tabs with Search as an ordinary tab. Each tab supplies only a Polaris icon asset visually; localized tab
names live in accessibility labels via `VaultTab`. The Home header magnifier and the search tab both land on
`SearchScreen`, which auto-activates `.searchable(isPresented:)` on appear. Do not restore
the custom shell overlay unless explicitly re-approved; prior custom glass/indicator motion caused switch
latency. For any future custom iOS-26 Liquid Glass API, guard with `#if compiler(>=6.2)` +
`#available(iOS 26, *)` and provide a material/solid fallback. Never glass on content cards/rows.

**Before UI work:** verify light + dark + Reduce Transparency + Reduce Motion + increased contrast; no
invisible text/icons after a theme switch; 44pt hit targets; new strings localized EN + VI + JA.

## Entitlements & capabilities (crash traps)

- `INFOPLIST_KEY_NSFaceIDUsageDescription` is required, or biometric Keychain access
  crashes. Set in `Project.swift` (both targets generate it).
- App Group `group.com.bervion.vaultify` + AutoFill Credential Provider are enabled on both
  bundle IDs (entitlements files + Apple Developer portal). The vault file (ciphertext,
  complete protection) lives in the shared container so the extension can read it.
- **iCloud/CloudKit is ENABLED**: the entitlements carry the container
  (`iCloud.com.bervion.vaultify`, provisioned in the portal) and `VAULTIFY_ICLOUD` is in
  Swift Active Compilation Conditions (`Project.swift`). CloudKit code still compiles behind
  the flag (`CloudSyncService.isConfigured`) so a fork without the provisioned container can
  turn it off. Runtime: **vault-item sync** is opt-in via `iCloudSyncEnabled` (off by
  default); **Approval Mode sharing** uses its own `approvalModeEnabled` flag and its own
  services — the two must never gate each other (plan ADR-2).
- iOS has no public API to read your own entitlements at runtime (`SecTask*` is macOS-only).

## Crypto

Argon2id is the vendored phc-winner-argon2 reference C (`VaultifyCore/CArgon2/ref.c`, **not**
opt.c), wired via a bridging header + `HEADER_SEARCH_PATHS=$(SRCROOT)/VaultifyCore/CArgon2`.
KAT: `Argon2id(password, somesalt, t=2, m=65536, p=1, len=32)` =
`09316115d5cf24ed5a15a31a3ba326e5cf32edc24702987c02b6566f61913cf7`.

## Analytics (GA4)

`Vaultify/Analytics/` — `AnalyticsEngine.shared.log(...)` with events from the **typed
catalog** (`AnalyticsEvents.swift`) only; never inline `AnalyticsEvent("...")` at call
sites, and every new factory gets an `auditSamples` entry (GA4 limits are test-enforced).
PRIVACY CONTRACT: parameters carry item TYPES, `AnalyticsBucket` counts, product IDs,
setting states — never item names/values, websites, search terms, or user content. App
target only (extensions must never link Firebase; products are `FirebaseAnalyticsCore` —
no IDFA — and `FirebaseCrashlytics`). Bulk flows wrap repository writes in `runSuppressed`
+ one summary event. Screens: `.analyticsScreen("snake_name")`. Works without
`GoogleService-Info.plist` (analytics dark); the real plist lives in `Vaultify/Resources/`.

## Crash reporting (Crashlytics)

`Vaultify/Analytics/CrashReporter.swift` + `CrashReportKeys.swift`. Shares Firebase's single
`configure()` gate with analytics, but has its OWN consent flag
(`SettingsStore.crashReportingEnabled`, opt-out) — turning analytics off must not silently keep
uploading crashes, and vice versa. Collection is off in DEBUG so dev crashes stay out of the
production dashboard.

PRIVACY CONTRACT — stricter than it looks, because a crash payload is not a typed event:
- Custom keys come from the typed `CrashReportKeys` catalog only, validated by a pure policy
  the same way `AnalyticsPolicy` validates events. Never pass a free-form string.
- Never call `setUserID` — it would link crash data to identity and contradict the privacy
  manifest's `Linked=false` declaration.
- Never log an interpolated `Error`: Loox errors can embed record ids, CloudKit zone/share
  names and file URLs. Categorise to a fixed identifier first.
- `precondition`/`fatalError` MESSAGES are uploaded. Do not interpolate paths or filenames.
- Extensions carry no Firebase, so a crash inside VaultifyAutoFill / VaultifyAutoFillMac /
  VaultifySafari is INVISIBLE here. Do not "fix" that by linking Firebase into an appex.
- A hang is not always a crash: Crashlytics sees a watchdog termination only when the OS kills
  the process. A recoverable main-thread stall leaves no report.

dSYMs upload from the fastlane release lane, not an Xcode run-script phase — the script's path
is derived-data-layout dependent and differs between a dev machine and the self-hosted runner,
where it fails silently. Use ONE mechanism.

## Verifying runtime behavior

stdout/console capture is unreliable here. Use a DEBUG file-based self-test: write to
Documents, read back with `simctl get_app_container <id> data`.

- Conventional commits (`feat:`, `fix:`, `chore:`, `refactor:`, `docs:`); no AI references.

## Don'ts

- ❌ Don't open or edit a committed `.xcodeproj` — edit `Project.swift`, then `tuist generate`.
- ❌ Don't commit the generated project, `Derived/`, or any secret.
- ❌ Don't gate Approval-Mode sharing code on `iCloudSyncEnabled` — it has its own
  `approvalModeEnabled` flag (control plane ≠ vault-item sync, plan ADR-2).
- ❌ Don't construct icons with `Image(systemName:)`, `Image(name)`, `Label(_, image:)` or
  `UIImage(named:)` — an `sf:` token is not an asset name and renders BLANK. Use `VaultIcon`
  (or `Image(vaultIcon:)` where a raw `Image` is genuinely required).
- ❌ Don't add an SF Symbol newer than iOS 17.3 — it compiles and renders nothing on the floor.
- ❌ Don't rewrite stored `iconAsset` values to migrate icons — resolve at read time
  (`LegacyIconMap`), or two devices on different builds stop converging.
- ❌ Don't ship user-facing text without a Vietnamese translation in `Localizable.xcstrings`
  (native) or in **both** `VaultifySafari/Resources/_locales/en` + `_locales/vi` (Safari
  extension web layer).
- ❌ Don't add a native→JS command to the Safari extension that returns vault field values —
  `getFillPayload` must stay the ONLY one (test-enforced), and content-script-reachable
  commands must never be able to summon Face ID.
- ❌ Don't put the word "build" in bash paths/log names (hook block).
