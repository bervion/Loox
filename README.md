# Vaultify

Private, offline, **zero-backend** password & passkey manager for iOS. Built with native
SwiftUI. Your vault is encrypted with Argon2id and never leaves the device — no account,
no server, no tracking.

## Highlights

- 🔐 **On-device only** — vault is an encrypted file in a shared App Group container; no backend
- 🧬 **Argon2id** key derivation (vendored reference C) + AES-GCM vault encryption
- 👤 **Face ID** unlock
- 🔑 **iOS AutoFill** for passwords **and passkeys** (Credential Provider extension)
- 🌏 **EN / VI** with an in-app language toggle
- ☁️ **Optional** iCloud (CloudKit) sync — off by default, compile-gated
- 📱 iPhone-only, iOS 17.6+

## Tech stack

| | |
|---|---|
| UI | SwiftUI (native, iPhone-only) |
| Crypto | Argon2id (vendored C, `VaultifyCore/CArgon2`) + CryptoKit |
| Project | Generated by **[Tuist](https://tuist.dev)** from `Project.swift` |
| CI/CD | GitHub Actions (self-hosted) + **fastlane** → TestFlight |
| Signing | fastlane **match** + App Store Connect API key |

## Requirements

- macOS + **Xcode 16+** (the team develops on Xcode 27 beta; CI runs a stable Xcode — the
  project is generated per-machine so either works)
- **Tuist 4** — `brew install tuist`
- For releases only: Ruby + Bundler (`gem install bundler`)

## Getting started

```bash
git clone git@github.com:bervion/Vaultify.git
cd Vaultify
tuist generate          # generates Vaultify.xcworkspace + .xcodeproj, then opens Xcode
```

In Xcode: select the **Vaultify** scheme and run (⌘R). The simulator needs no signing; a
physical device uses automatic signing under team `WDNL2F75V7`.

> The `.xcodeproj` / `.xcworkspace` are **generated** (gitignored). Always open the
> **workspace**, never a committed `.xcodeproj`.

## Development workflow

1. **Generate / open**: `tuist generate` (or `make gen` then open `Vaultify.xcworkspace`)
2. **Code & run** in Xcode as usual (scheme **Vaultify**)
3. **Add / remove / rename** a `.swift` or `.c` file → create it under `Vaultify/`,
   `VaultifyCore/`, or `VaultifyAutoFill/`, then run `tuist generate` again (Tuist globs
   sources at generation time)
4. **Change project config** (settings, capabilities, dependencies) → edit `Project.swift`,
   then `tuist generate`. Use `tuist edit` for manifest autocomplete.
5. **Compile check** (app + extension): `make check`
6. **Commit** `Project.swift` + source — **never** the generated project. Use
   [conventional commits](https://www.conventionalcommits.org) (`feat:`, `fix:`, `chore:` …).

## Releasing → TestFlight

Fully automated. From `main` with a clean tree:

```bash
make release     # auto-bump version from commits + AI release notes + tag → TestFlight
make beta        # quick build, no version bump → TestFlight (vX.Y.Z-beta.N)
make hotfix      # force a patch release
make version     # show current version / build / last tag
make notes       # preview AI release notes (no commit)
```

`make release` bumps `MARKETING_VERSION` / `CURRENT_PROJECT_VERSION` in `Project.swift`,
generates EN/VI release notes (Claude CLI), updates `CHANGELOG.md`, commits, tags `vX.Y.Z`,
and pushes. The tag triggers GitHub Actions on a self-hosted runner → fastlane `match`
signs the app + extension → uploads to TestFlight.

**First-time setup** (App IDs, certificates repo, App Store Connect API key, GitHub
secrets, self-hosted runner) is documented in **[docs/deployment-guide.md](docs/deployment-guide.md)**.

## Security model (brief)

- Master password → **Argon2id** → vault key; vault is an encrypted file in the
  `group.com.bervion.vaultify` App Group container (so the AutoFill extension can read it)
- No network, no analytics, no account. Optional iCloud sync is **off** unless built with
  the `VAULTIFY_ICLOUD` flag and the iCloud capability enabled.
